# MAF 1.28 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the existing Microsoft Agent Framework dependencies to 1.28 and align the selected Microsoft.Extensions and OpenTelemetry package cohorts without changing runtime behavior.

**Architecture:** Keep NuGet versions in the root `Directory.Packages.props` and leave project `PackageReference` items versionless. Preserve the existing MAF Adapter, Gateway A2A, and Core boundaries; make source changes only if the new package APIs produce a concrete compile failure.

**Tech Stack:** .NET 10, NuGet Central Package Management, Microsoft Agent Framework, A2A, Microsoft.Extensions.AI, OpenTelemetry, xUnit.

## Global Constraints

- `Microsoft.Agents.AI` target version: `1.28.0`.
- `Microsoft.Agents.AI.Hosting.A2A` and `Microsoft.Agents.AI.Hosting.A2A.AspNetCore` target version: `1.28.0-preview.261106.1`.
- A2A and A2A.AspNetCore target version: `1.0.0-preview4`.
- Microsoft.Extensions.AI packages target version: `10.11.0`.
- Other currently pinned Microsoft.Extensions packages target version: `10.0.14`.
- OpenTelemetry API, Exporter, and Hosting packages target version: `1.20.1`; AspNetCore and Http instrumentation target version: `1.20.2`; Runtime instrumentation target version: `1.20.1`.
- Keep versions in the root `Directory.Packages.props`; project `PackageReference` items remain versionless.
- Do not add non-direct dependency pins or update unrelated package families.
- Keep MAF outside Core; do not change NativeAOT compatibility declarations or add reflection-heavy paths to Core.
- Preserve A2A wire behavior, streaming, session serialization, and Gateway error behavior.
